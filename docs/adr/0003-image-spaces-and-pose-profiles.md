# ADR 0003: Separate full-frame QA rectification from pose-input profiles

- Status: Accepted
- Date: 2026-08-19

## Context

Full-frame fisheye undistortion and stereo rectification are valuable for calibration gates,
epipolar QA, triangulation, and visual diagnosis. They do not automatically provide the best
input domain for a top-down perspective pose model, especially near the fisheye periphery.
Changing model input silently would also make runs incomparable.

## Decision

RTMDet remains on native distorted frames. Full-frame undistorted and rectified images remain
QA/debug artifacts rather than mandatory model inputs. RTMPose has two explicit, versioned
profiles:

- `baseline_native_v1`, the backward-compatible default using native-fisheye proposals and
  the model's top-down crop;
- `virtual_perspective_kb4_v1`, an opt-in hand-centred pinhole crop generated by calibrated
  KB4 ray mapping and mapped back to named source/rectified spaces.

Every saved point and overlay declares its pixel space. A candidate that cannot be represented
by one perspective crop is rejected locally with evidence retained; it does not silently fall
back to another profile.

## Consequences

- Calibration QA and model input are no longer conflated.
- Native and virtual-profile results remain attributable and suitable for ablation.
- The virtual profile is implemented, but its presence is not a claim of target-domain GT
  accuracy or production readiness.
- New image adaptations require a new profile/policy identity and explicit coordinate mapping.
