# 双目鱼眼手部骨骼 Pipeline v2 迭代报告

## 1. 当时算法遇到的问题

在 120 组双目帧的历史基线中，只有 113 帧得到双手匹配。Raw 3D 存在明显的骨长异常和
时序跳变，并产生了一条额外的短轨。逐帧 MANO 使用零姿态冷启动和 40 次等权优化，
233 个拟合结果全部未通过 20 mm 门禁，因此最终输出实际只是 Raw 3D 的 XYZ EMA，而不是
真正的 Temporal MANO。

## 2. 推测原因

RTMDet 和 RTMPose 直接处理原始鱼眼图，可能存在透视模型与鱼眼图像之间的输入域偏差；
但由于没有 2D GT 和成对消融，这一点仍属于推测。跨视角关联只依赖 rectified-y，逐关节
线性三角化也缺少可靠的不确定度、解剖和时序约束，因此极线一致的错配仍可能生成不合理
的 3D 骨骼。

MANO 失败有更直接的收敛证据：同一代表帧将迭代次数从 40 增加到 200/500 后，最佳 RMSE
从 29.33 mm 降至 9.55/7.78 mm，说明原 fitter 明显欠收敛。后续失败帧还集中出现局部
解剖离群点，同时鲁棒优化目标与普通 RMSE 验收口径并不一致。

## 3. 具体解决方式

- 围绕手框构造局部虚拟透视 crop：RTMDet 仍处理原始鱼眼图，RTMPose 改在 crop 域推理；
- 检测采用 0.30 seed、0.20 recovery 和 top-4 候选池，再通过双目几何筛选最终两只手；
- 使用 Huber 鲁棒双目融合和掌心支持门禁；tracker 改用固定掌心锚点、速度预测、
  one-to-one 分配和 TTL 恢复；
- MANO 改用 mean-pose 初始化、最多 200 次迭代、accepted-state warm-start、cold recovery
  和 best-so-far；
- 对首轮未通过的 MANO 结果，最多降权 10% 的高残差关节后重新拟合，同时要求至少 15 个
  有效支持点、inlier RMSE ≤ 20 mm、full RMSE ≤ 40 mm；Raw 观测始终保持不变。

此外，SimCC 原始分数不再被误当成概率；单个无法由透视 crop 表示的候选也改为局部拒绝，
不再导致整条任务终止。

## 4. 解决效果

在同一 120-pair 数据上：

- 双手匹配由 113/120 提升到 120/120；
- Raw 输出由 233 增至 238，有效关节由 4,634/4,893 增至 4,764/4,998；
- 轨迹由三条变为两条长期轨迹；
- MANO 产出先由 0/233 提升至 213/238，加入二阶段离群点降权后进一步提升至
  234/238（98.319%）；
- Raw fallback 从 25 帧降至 4 帧；最终 inlier RMSE P95 为 17.897 mm，full RMSE 最大值为
  33.140 mm，均通过 V7.1 门禁。

本轮明显改善了双手召回数量、tracking 稳定性和 MANO 产出率，但整体质量仍未完全解决：
ordinary full RMSE P95 为 25.327 mm，仍高于原定的 20 mm 门槛；Raw 3D 仍存在异常骨长；
virtual crop 尚无 2D GT 或成对消融证明优于 native 输入；当前时序阶段仍是 causal XYZ EMA，
而不是 Temporal MANO。以上 RMSE 也只是 MANO 对 Raw 3D 的拟合残差，不能视为相对真实
3D GT 的精度。
